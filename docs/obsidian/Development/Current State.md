# Текущее состояние

[[Erida]] · [[Roadmap|Дорожная карта]] · [[Next Steps|Ближайшие шаги]]

Состояние зафиксировано по исходному коду и рабочему дереву на момент анализа. Рабочее дерево **нечистое**: помимо этих документационных файлов в нём есть незакоммиченные изменения в импорте папки, UI, Pinia store и Tauri-адаптерах. Описанные ниже возможности включают эти изменения, но они ещё не являются частью `HEAD`.

## Приложение и UI

- Nuxt 3 работает как клиентское SPA (`ssr: false`), со строгим TypeScript, Pinia и Tailwind CSS.
- Базовый layout содержит навигацию **Library** (`/`) и **Playlists** (`/`).
- Главная страница при загрузке запрашивает список треков. Она показывает число треков, пустое состояние, таблицу или общее сообщение об ошибке загрузки.
- Таблица выводит title, artist, album и длительность. Для отсутствующих альбома и длительности выводится тире; длительность форматируется как `m:ss`.
- На странице библиотеки есть кнопки импорта отдельных файлов и папки. Во время импорта кнопки блокируются; ошибка импорта показывается в компоненте кнопки.
- Страница плейлистов отображает два статических demo-объекта (`Late night` и `Focus`). Реального хранилища, загрузки или редактирования плейлистов в коде нет.

## Music Core и импорт

- Музыкальная логика вынесена в `core/music-library`: доменные типы `Track` и `MusicLibraryRepository`, application use case `ImportLocalTracks`, инфраструктурные Tauri-адаптеры и composition root.
- Nuxt-плагин создаёт приложение библиотеки и предоставляет UI только репозиторий и фасад импорта; UI не вызывает файловую систему напрямую.
- Импорт отдельных файлов открывает нативный Tauri dialog с фильтром `mp3`, `flac`, `m4a`, `wav`.
- Импорт папки открывает выбор каталога, а Rust-команда рекурсивно находит файлы тех же расширений без учёта регистра и сортирует пути. Этот путь импорта присутствует только в текущих незакоммиченных изменениях.
- Rust-команда читает title, artist, album и duration через `lofty`. Если чтение метаданных не удаётся, frontend всё равно создаёт запись: title берётся из имени файла, artist — `Unknown Artist`, album и duration становятся `null`.
- Идентификатор трека генерируется в браузере через `crypto.randomUUID()`. Дедупликация по пути файла не реализована.

## Хранение и нативная часть

- Tauri регистрирует команды `read_audio_metadata`, `discover_audio_files`, `add_library_track` и `list_library_tracks`; последняя пара использует SQLite.
- База `music-library.sqlite3` размещается в application data directory приложения. Инициализация применяет транзакционную миграцию SQLite `user_version = 1`.
- Таблица `tracks` хранит порядок вставки, уникальный `id`, title, artist, необязательные album/duration и один из источников: `local` с locator либо `service` с provider/external id. Проверяется неотрицательная конечная длительность.
- Записи перечисляются в порядке вставки. Повторный `id` отклоняется SQLite; одинаковый local locator допускается.
- В доменной модели и SQLite предусмотрен источник `service`, но интеграции с музыкальными сервисами, UI для него и вызовов такого импорта нет.
- В `src-tauri/capabilities/default.json` разрешены стандартные возможности Tauri и `dialog:allow-open`; для доступа к файлам используются нативные Rust-команды.

## Проверки и поставка

- В репозитории есть 9 Vitest-файлов, покрывающих UI импорта, store, application/core composition и Tauri TypeScript-адаптеры. В текущем анализе `npm.cmd test` завершился успешно: **9 файлов, 33 теста**.
- Rust-модули хранения, поиска файлов и чтения метаданных содержат unit-тесты. В текущем анализе `cargo test --locked` завершился успешно: **19 тестов** в библиотеке Rust; у binary и doc-tests тестов нет.
- Pull request CI выполняет `npm ci`, `npm run prepare`, `npm test`, `npm run build`, а также `cargo check --locked` и `cargo test --locked` в `src-tauri`.
- Tauri-конфигурация собирает Nuxt static output и содержит desktop window 800×600. Фактическая сборка приложения и запуск desktop-окна в этом анализе не выполнялись.

## Неподтверждённое или отсутствующее

- Drizzle ORM упомянут в проектных инструкциях, но не найден в `package.json`, `Cargo.toml` или исходниках. Текущая SQLite-реализация использует `rusqlite` напрямую.
- В коде не найдены подтверждения playback, очереди воспроизведения, удаления/редактирования треков, поиска, управления плейлистами или внешних музыкальных интеграций. Их статус не следует выводить из названий проекта или типов источников.
