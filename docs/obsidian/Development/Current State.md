# Текущее состояние

[[Erida]] · [[Roadmap|Дорожная карта]] · [[Next Steps|Ближайшие шаги]]

Документ отражает состояние `main` после завершения local artwork fallback (#54).

## Приложение и UI

- Nuxt 3 работает как клиентское SPA (`ssr: false`) с TypeScript, Pinia и Tailwind CSS.
- Tauri 2 используется как desktop-оболочка приложения.
- Основные разделы интерфейса — Library и Playlists.
- Library отображает локальную музыкальную библиотеку с title, artist, album и duration.
- Поддерживается импорт отдельных аудиофайлов и рекурсивный импорт папок.
- Поддерживается drag & drop файлов и папок.
- Для трека доступна отдельная страница Track Details.
- Track Details отображает метаданные, локальный путь и artwork либо placeholder.
- Трек можно удалить из библиотеки. Исходный аудиофайл при этом не удаляется.
- Playlists пока остаётся демонстрационным разделом без полноценного хранилища и управления плейлистами.

## Music Core и импорт

- Основная логика музыкальной библиотеки находится в `core/music-library`.
- UI не работает напрямую с файловой системой, SQLite или Tauri commands.
- Application layer координирует импорт через порты и инфраструктурные адаптеры.
- Поддерживаемые локальные форматы: MP3, FLAC, M4A и WAV.
- Rust выполняет рекурсивный поиск поддерживаемых аудиофайлов.
- Метаданные читаются через `lofty`.
- При отсутствии или ошибке чтения метаданных используются fallback-значения:
  - title — имя файла;
  - artist — `Unknown Artist`;
  - album — `null`;
  - duration — `null`.
- Идентификаторы треков генерируются через `crypto.randomUUID()`.
- Дедупликация одинаковых локальных файлов пока не реализована.

## Artwork

- Во время импорта Erida пытается извлечь embedded artwork из аудиофайла.
- Извлечение выполняется в Rust через `lofty`.
- Поддерживаются JPEG, PNG, GIF и BMP.
- Artwork проверяется по формату и magic bytes, а максимальный размер ограничен 10 MiB.
- Извлечённые изображения кэшируются в application data directory.
- Если embedded artwork отсутствует или его извлечение завершается ошибкой, Rust ищет в каталоге аудиофайла `cover.jpg`, `cover.png`, `folder.jpg`, затем `folder.png`; сопоставление имён регистронезависимо.
- Локальные изображения копируются без изменения в `artwork/local`, а `Track.artworkRef` получает строго валидируемый ref вида `local/<track-id>.jpg|png`.
- В `Track` хранится `artworkRef`, а не абсолютный filesystem path.
- SQLite сохраняет `artworkRef`, поэтому artwork сохраняется после перезапуска приложения.
- UI получает готовый `artworkUrl` через отдельный resolver.
- Track Details отображает artwork либо placeholder при его отсутствии/ошибке загрузки.
- Native smoke test подтвердил полный путь: import → cache → SQLite → restart → display.

## Хранение и нативная часть

- Локальная библиотека хранится в SQLite через Rust и `rusqlite`.
- База `music-library.sqlite3` размещается в application data directory.
- Текущая схема использует SQLite `user_version = 2`.
- Таблица `tracks` хранит основные метаданные, источник трека и nullable `artwork_ref`.
- Поддерживаются источники `local` и `service`, однако интеграции с музыкальными сервисами ещё не реализованы.
- Добавление, чтение и удаление записей выполняются через focused Tauri commands.
- Отсутствие исходного локального файла не приводит к автоматическому удалению записи из библиотеки.
- Drizzle ORM не используется: SQLite принадлежит Rust/Tauri-слою и доступен через `rusqlite`.

## Известный технический долг

- Issue #50 фиксирует воспроизводимый dev-only конфликт Nuxt/Vite вокруг `#app-manifest`.
- Ошибка возникает из-за stale Vite optimizer metadata после изменения сгенерированного Nuxt manifest state.
- Проблема не связана с архитектурой Tauri и не блокирует production build.
- Временный workaround — инвалидировать `node_modules/.cache/vite/client/deps/_metadata.json`.
- Постоянный workaround через `vite.optimizeDeps.force` проверен, но пока не принят из-за стоимости принудительной переоптимизации при каждом dev-запуске.
- Очистка orphaned artwork после удаления трека пока не реализована.
- Дедупликация импортированных локальных треков пока не реализована.
